# 빙글링 1.3 설계: 자체 캡처, 바로 스포이트, 편집 창 추가 기능, 바로 꾸미기, 가릴 곳 찾기

- 날짜: 2026-10-22
- 바탕: `main` `c1a910c` (1.2.1)
- 상태: 사용자가 체험 페이지(https://claude.ai/artifact/XFYKefoRQcMYTN9GRNTPJG)를 보고 A~D를 모두 고름("다 하자").
  아래 "정한 값"은 Claude가 정했다. 사용자가 바꾸자고 하면 바꾼다.
- 조사 근거: 코드 조사 보고(대화 기록), OCR 시험(Windows PowerShell 5.1에서 `Windows.Media.Ocr`가 한국어로 0.4초에
  전화번호·이메일과 위치를 읽음, `FaceDetector.IsSupported` = true).

## 0. 목적

- 캡처하고 표시하고 붙여 넣는 흐름을 파일 없이, 빙글링 안에서 끝낸다.
- 화면 어디서든 색 코드를 바로 얻는다.
- 편집 창에서 자주 쓰는 표시(흐림, 스포트라이트, 색 찍기)를 더한다.
- 같은 꾸미기를 여러 캡처에 창 없이 바로 건다.
- 가릴 것을 사람이 하나하나 찾지 않아도 되게 후보를 찾아 준다.

## 1. 공통 규칙

- 원작 Filee와 기존 규칙을 지킨다: 사용자에게 보이는 글은 6개 언어(i18n) 모두, `Filee.*` 이름 유지, 새 코드는 되도록 새 파일.
- **설정 호환**: 새 enum 값은 맨 끝에, `LenientEnumJsonConverter`를 붙인다. 변환기가 없는 enum(`TriggerKind` 등)에는 새 값을
  넣지 않는다(모르는 값이면 설정 파일 전체가 초기화된다). 새 정보는 새 속성으로 넣는다(모르는 속성은 이전 버전이 무시).
- 설정 스키마 번호(22)는 올리지 않는다. 기존 사용자에게 새 기본값을 넣을 때는 "없으면 한 번 넣기"(로드할 때 확인)를 쓴다.
- Windows 전용 기능은 `IPlatformServices`의 기본 구현(빈 결과) 뒤에 둔다. Linux·macOS 빌드는 그대로 돌아야 한다.
- 버전은 1.3.0. 릴리스는 다 끝난 뒤 사용자에게 묻는다.

## 2. A. 빙글링 캡처와 바로 스포이트

### 2.1 단축키
- `TriggerGesture`에 새 속성 `Action`(`TriggerAction { Donut, Capture, PickColor }`, Lenient, 기본 Donut)을 더한다.
  `Kind`는 KeyChord 그대로다. 이전 버전은 Action을 모르니 그 단축키로 링을 연다(설정은 지켜짐).
- 같은 김에 `TriggerKind`, `TriggerScope`, `TriggerMouseButton`에도 Lenient 변환기를 붙인다(다음 확장 대비).
- **정한 값**: 새 사용자 기본 단축키
  - 화면 캡처: **Ctrl+Alt+S**, 범위 "모든 곳", 켜짐
  - 바로 스포이트: **Ctrl+Alt+C**, 범위 "모든 곳", 켜짐
- 기존 사용자: 로드할 때 Action이 Capture/PickColor인 단축키가 없고 `AppSettings.ScreenShortcutsAdded`(새 bool)가
  false면 두 단축키를 넣고 플래그를 켠다(한 번만). 같은 키 조합이 이미 있으면 꺼진 채로 넣는다.
- 설정 › 단축키: 키 조합 단축키에 "동작" 고르기(링 열기 / 화면 캡처 / 색 찍기)를 더한다. 요약 글자(GestureText)에도 동작을 넣는다.
- 첫 번째 KeyChord를 링 단축키로 보는 곳(Linux Thunar 등)은 `Action == Donut`인 것만 본다.
- 트레이 메뉴에 "화면 캡처", "색 찍기"를 더한다(메뉴가 사라진 뒤 찍도록 잠깐 기다림).

### 2.2 캡처 화면 (CaptureWindow)
- 단축키를 누르면 **커서가 있는 모니터**를 `CaptureScreen`으로 찍고(창을 띄우기 전에), 그 모니터를 덮는 최상위 창에 멈춘 화면을 보여 준다.
  여러 모니터를 한꺼번에 덮는 것은 다음 단계로 미룬다(정한 값).
- 화면을 어둡게 덮고, 끌어서 영역을 고른다. 고른 곳은 밝게, 크기(픽셀)를 표시한다. 너무 작으면(8px 미만) 무시.
- 위쪽 도구 줄: **영역 / 화면 전체 / 스포이트 / 닫기(Esc)**.
- 영역을 고르면 그 아래(자리가 없으면 위)에 **편집 / 복사 / 저장** 단추.
  - 복사: 고른 부분을 그림으로 클립보드에 넣고, "복사했어요"를 잠깐(0.6초) 보여 준 뒤 닫는다. 키 Enter, Ctrl+C.
  - 저장: 고른 부분을 PNG로 **사진\Bingling** 폴더에 저장한다(정한 값). 이름은 `캡처 2026-10-22 131500.png`
    (앞말은 언어마다: i18n). 저장은 PNG 변환 작업으로 돌려서 결과 카드(미리보기·복사·폴더 열기)가 뜨게 한다. 키 Ctrl+S.
  - 편집: 고른 부분을 임시 PNG(위와 같은 이름)로 쓰고 **그리기** 창을 연다. 그 창의 저장은 사진\Bingling에 저장하고,
    복사는 지금처럼 클립보드로 간다. 임시 파일은 창이 닫히고 작업이 끝나면 지운다.
- 스포이트 모드: 멈춘 화면 위에서 커서 옆에 확대경(13×13 픽셀을 120px로, 가운데 칸 표시, HEX 표시). 누르면 2.4의 색 카드.
- 오른쪽 클릭이나 Esc: 닫기. 찍은 화면은 창을 닫을 때 놓아 준다.

### 2.3 바로 스포이트 (PickColorWindow)
- 단축키를 누르면 커서가 있는 모니터를 찍고, 그 모니터를 거의 투명한 최상위 창(`#01000000`)으로 덮는다. 화면은 그대로 보이고 커서 옆에 확대경만 뜬다.
- 누르면 그 자리 색을 찍어 **HEX를 바로 복사**하고 색 카드를 띄운다. Esc나 오른쪽 클릭은 그만두기.

### 2.4 색 카드 (ColorCardWindow)
- 찍은 자리 근처에 작은 카드: 색 견본, **HEX**, RGB, HSL, 단추 **HEX 복사 / RGB 복사 / HSL 복사**, "HEX를 복사했어요" 표시.
- 6초 뒤, Esc, 카드 밖 클릭이면 사라진다. 복사 단추를 누르면 그 형식으로 바꿔 복사한다.

## 3. B. 편집 창 추가 기능

### 3.1 흐리게 가리기
- `RedactMode.Blur`를 끝에 더한다(이전 버전은 Black으로 읽음: 더 가리는 쪽으로 물러섬).
- 2026-10-19 설계는 "흐림은 복원될 수 있어 넣지 않는다"고 했다. 사용자가 1.3에서 넣기로 했다. 그래서 **복원할 수 없게**
  그린다: 상자를 먼저 모자이크(지금 칸 크기)로 바꾼 다음 그 위를 흐리게(시그마 ≈ 칸 크기의 0.6) 한다. 세기는 하나만 둔다.
- 칩 "흐림", 키 **U**. 툴팁 문구 6개 언어.
- 미리보기와 저장이 같은 `ImageEditRenderer`를 쓰므로 둘 다 같은 모습.

### 3.2 스포트라이트
- `AnnotationKind.Spotlight`를 끝에 더한다(이전 버전은 Pen으로 읽음). 키 **S**, 그리기 도구 줄 10번째 칸.
- 사각형처럼 두 모서리로 그린다(Shift: 정사각형). 고르기, 옮기기, 지우기, 되돌리기는 다른 그림과 같다.
- 그리기: 한 파일의 스포트라이트들을 모아, 그 바깥을 검정 55%로 한 번 덮는다(겹쳐도 더 어두워지지 않음).
  가장자리는 둥글게(짧은 변의 1%). 색과 굵기는 쓰지 않는다. 스포트라이트는 다른 그림보다 먼저(아래에) 그린다.

### 3.3 편집 창 스포이트
- 그리기 창과 배경 넣기 창의 "사용자 색" 옆에 **스포이트** 단추(키 **I**). 켜면 그림 위에 확대경, 누르면 그 색이
  사용자 색(HEX)이 되고 스포이트는 꺼진다. Esc로 그만둔다.
- 사용자 색 칸 옆에 **복사** 단추: 지금 색의 HEX를 복사한다.
- 배경 넣기 창은 결과 전체(배경 포함)를 보여 주므로, 찍는 색도 보이는 그대로(배경 포함)에서 찍는다.

## 4. C. 창 없이 바로 꾸미기

- 새 도구 프리셋 **quick-background**: `Kind = Tool`, `Tool = AddBackground`, 새 속성 `Preset.RunWithLastChoices = true`
  (이전 버전은 이 속성을 모르니 배경 넣기 창을 연다). 이름 "배경 바로"(짧은 이름도), 결과 PNG, 이름 패턴 배경 넣기와 같음.
- 링에서 놓으면 창을 열지 않고 `ImageToolSettings.Background`(지난 배경 설정)로 바로 변환한다. 정지 그림만 받는 검사와
  안내는 배경 넣기와 같다. 진행은 보통 변환처럼 링과 카드에 나온다(1.2.1의 사진 결과 카드).
- 기존·새 라이브러리 모두: 이 프리셋이 없으면 로드할 때 넣고(배경 넣기 다음 자리), **이미지 링에 자리가 있으면(12칸 미만)
  끝에 올린다**(정한 값). 프리셋이 생긴 뒤에는 다시 올리지 않는다(사용자가 빼면 그대로).
- 오른쪽 클릭 편집(프리셋 편집 창)은 다른 도구처럼 없다. 배경은 배경 넣기 창에서 정한다는 안내를 툴팁에 쓴다.

## 5. D. 가릴 곳 자동 찾기

- 가리기 창 패널에 **가릴 곳 찾기** 단추. 파일이 하나일 때만 켠다(가리기 상자는 모든 파일에 같이 쓰이므로).
- Windows: `IPlatformServices.FindTextAndFacesAsync(imagePath)`(기본 구현은 빈 결과)를 새로 둔다. Windows 구현은 Windows
  PowerShell 5.1(`%WINDIR%\System32\WindowsPowerShell\v1.0\powershell.exe`)로 짧은 스크립트를 돌려 `Windows.Media.Ocr`의
  줄·단어 상자와 `FaceDetector`의 얼굴 상자를 받는다. 결과는 UTF-8 JSON 파일로 받는다(콘솔 인코딩 문제 피함).
  - 큰 그림은 OCR 최대 크기(`OcrEngine.MaxImageDimension`)에 맞게 줄여서 넣고 좌표를 되돌린다.
  - OCR 언어가 없으면(엔진 null) "이 PC에는 글자 인식 언어가 없어요"를 보여 준다. 얼굴은 그래도 찾는다.
- Core: `SensitiveFinder`가 단어·줄 상자에서 후보를 고른다. 종류: **전화번호, 이메일, 주민등록번호, 카드번호, 주소, 얼굴**.
  이름은 인식이 불안정해서 넣지 않는다(정한 값). 규칙은 정규식(한국 형식 위주, 공백·점·하이픈 허용).
- 패널: 찾은 후보를 종류 칩과 글자로 목록에 보여 주고(체크 상자, 처음엔 모두 켜짐), 그림 위에도 종류별 색 테두리로
  보여 준다. **고른 곳 가리기**를 누르면 그 상자들을 지금 방식(검은 상자·모자이크·흐림)으로 더한다(되돌리기 한 단계).
- 찾는 동안 "찾는 중…" 표시, 실패하면 한 줄 안내. 인식은 PC 안에서만 한다.

## 6. 테스트와 검토

- 기능마다 테스트를 먼저 쓴다(TDD). 위치: Core(설정 호환, 정규식), Engines(렌더러: 흐림·스포트라이트), App(뷰모델·창,
  헤드리스), Platform(Windows 화면 캡처·OCR: 화면 없는 세션이면 건너뜀).
- 기능 묶음(A, B, C, D)마다 Codex 검토를 받고 고친다.
- 마지막에 전체 테스트, 설치 파일·포터블 빌드, 사용 설명서·README·변경 기록·친구용 PDF 갱신.

## 7. 하지 않는 것

- 여러 모니터를 한 번에 덮는 캡처, 창 하나 캡처, 스크롤 캡처, 동영상 캡처.
- 스포이트 색 기록 저장, 색 형식 설정.
- 이름 자동 찾기, 클라우드 OCR.
