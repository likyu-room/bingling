# Filee Plus 설계: Tangerine식 도구와 모양을 Filee에 더하기

- 날짜: 2026-10-19
- 기반: [KnifeLemon/Filee](https://github.com/KnifeLemon/Filee) `d7c46e9` (1.12.0, MIT)
- 상태: 설계 승인 대기 (섹션 1·2는 대화에서 승인, 3~7은 사용자가 "괜찮은 대로, 편의성 고려해서"라고 맡김)

## 0. 목적과 성공 기준

**목적.** 맥 앱 Tangerine의 사용감을 윈도우에서 그대로 쓴다. 파일을 끌다가 Shift를 누르면 커서 둘레에 원형 메뉴가 뜨고, 칸에 놓으면 결과가 원본 옆에 저장된다. 처리는 모두 내 PC에서 한다. 이미 같은 방식으로 이미지·문서 변환을 하는 Filee를 포크하고, Tangerine에만 있는 도구(자르기, 배경 추가, 가리기, 주석)와 유리 같은 모양을 더한다. 다른 사람에게도 나눠 준다.

**사용자가 직접 정한 것**
- 드래그 + Shift 원형 메뉴는 꼭 있어야 한다.
- 이미지와 문서 형식 변환이 모두 돼야 한다(Filee가 이미 한다).
- Filee의 기능은 다 살리고, 개선할 게 있으면 한다.
- 주석과 유리 효과는 어렵더라도 넣는다.

**성공 기준**
1. 탐색기나 바탕화면에서 이미지를 끌다 Shift를 누르면 도넛이 뜬다. 형식 칸에 놓으면 변환된 파일이 원본 옆에 생기고, 원본은 그대로 있다.
2. 도구 링에서 6가지 도구를 쓸 수 있다. 편집 창의 미리보기와 저장 결과가 같다.
3. 피치 글래스 테마에서 도넛 뒤 화면이 흐리게 비친다(Windows 10·11).
4. 원본 Filee와 한 PC에 같이 깔려도 서로 설정이나 메뉴를 건드리지 않는다.
5. 기존 Filee 테스트와 새 테스트가 모두 통과하고, `dotnet format --verify-no-changes`도 통과한다.

## 2. 도구 칸과 도구 링

**사용 흐름**
1. 이미지 파일을 끌고 Shift를 누르면, 형식 칸들 사이에 강조색 **'도구' 칸**이 하나 함께 보인다.
2. 도구 칸에 머물거나 바깥으로 밀면 바깥쪽에 도구 링이 펼쳐진다. 칸은 자르기, 배경 추가, 가리기, 주석, 압축, 메타데이터 지우기다.
3. 놓은 칸에 따라 동작이 나뉜다.
   - 압축, 메타데이터 지우기: 창 없이 바로 처리하고 알림 카드만 띄운다.
   - 자르기, 배경 추가, 가리기, 주석: 도넛이 닫히고 편집 창이 열린다. '저장'을 누르면 처리한다.
4. Ctrl+Alt+Space(선택한 파일로 열기)나 탐색기 메뉴로 연 도넛에서도 클릭으로 똑같이 동작한다.

**구현 연결**
- 도구 링은 기존 `PresetKind.Group`이다. 내장 그룹 `tools`의 `SubPresetIds`는 위 6개 칸이며, `MaxSubPresets = 6`을 꽉 채운다.
- 새 값 `PresetKind.Tool`을 만들고 `Preset.Tool`(enum `ImageToolKind`: `Crop`, `AddBackground`, `Redact`, `Annotate`)를 추가한다. Tool 프리셋은 Group처럼 프리셋 고르는 곳에 나오지 않는다. 프리셋 목록, 감시 폴더, `filee --preset`이 그런 곳이다. 창이 필요해서다.
- 압축과 메타데이터 지우기는 보통 프리셋이다. `BuiltInData.Tool(...)` 도우미로 만들고, 다른 곳에서도 쓸 수 있다.
  - `compress-image`: `TargetFormat = "*"`(원본 형식), 품질 80, 메타데이터 지움, `{name} Compressed`. PNG는 손실 없이 최대 압축 수준만 쓴다.
  - `strip-metadata`: `"*"`, 품질 95(회전 프리셋과 같은 이유), 메타데이터 지움, `{name} Clean`.
- 도구 칸은 그룹 칸 중 하나지만 색이 다르다. `DonutItem`에 강조 표시 값을 하나 더한다.
- `RadialController.Convert`에서 Tool 프리셋을 받으면 아래 순서로 처리한다.
  1. 도넛을 닫는다.
  2. **드롭 처리가 끝난 뒤에** `Dispatcher.UIThread.Post`로 편집 창을 연다. 드롭 처리 안에서 창을 열면 탐색기가 멈춘다. 탐색기는 드롭이 끝날 때까지 기다리기 때문이다.
  3. 창 결과(`ImageEdit`, 취소하면 `null`)를 프리셋 복사본의 `Image.Edit`에 넣는다.
  4. 기존 변환 서비스로 작업 줄에 넣는다. 그래서 진행률, 실패 표시, 알림 카드, 이름 충돌 처리(`(2)`)가 기존 변환과 같다.
- **도구를 쓸 수 있는 파일:** 이미지 엔진(Magick)이 읽는 한 장짜리 래스터 이미지(JPG, PNG, WEBP, HEIC, AVIF, BMP, TIFF, 움직이지 않는 GIF 등)만 해당한다. 다음 경우에는 도구 칸이 꺼진 상태로 보이고 이유를 알려 준다.
  - 움직이는 GIF, 여러 쪽 TIFF, SVG, PDF·문서
  - 이미지와 다른 파일을 섞어 끌었을 때
- 도구 링의 칸 순서와 표시 여부는 기존 '원형 툴바' 설정 화면에서 바꾼다. 이미지용 기본 프로필에 `tools` 칸이 들어간다.

**저장 이름과 형식.** 모두 원본 옆에 저장하고 원본은 그대로 둔다.

| 도구 | 이름 | 형식 |
|---|---|---|
| 자르기 | `{name} Cropped` | 원본과 같음 |
| 배경 추가 | `{name} with background` | PNG |
| 가리기 | `{name} Redacted` | 원본과 같음, 메타데이터 항상 지움 |
| 주석 | `{name} Annotated` | 원본과 같음 |

## 3. 편집 창 (공통)

```
┌───────────────────────────────────────────────────────────┐
│ 자르기 · 사진.jpg                         3개 중 1   ‹  ›   │
├─────────────────────────────────────────┬─────────────────┤
│                                         │  도구별 패널     │
│            이미지 미리보기                │  (비율, 색,      │
│     (창에 맞춤 · 휠 확대 · 끌어서 이동)    │   여백 등)       │
│                                         │                 │
├─────────────────────────────────────────┴─────────────────┤
│ 3개 파일에 함께 적용돼요          [초기화]  [취소]  [저장 ⏎] │
└───────────────────────────────────────────────────────────┘
```

**창**
- 하나의 창 `ImageToolWindow`에서 도구에 따라 오른쪽 패널(UserControl)만 바뀐다.
- 드롭한 모니터에서 커서 가까이 열린다. 크기는 그림에 맞추되 작업 영역의 80%를 넘지 않는다.
- 열리면 앞으로 나오고 키보드 포커스를 가진다. 도넛 창은 활성화되지 않는 창이라서 일부러 활성화해야 한다.
- 앱 테마(밝게/어둡게, 강조색)를 따른다. 피치 글래스를 고르면 강조색이 귤색이 된다.

**편의 기능 (모든 도구 공통)**

| 동작 | 키 |
|---|---|
| 저장 | Enter |
| 닫기 | Esc. 주석에 그린 게 있으면 한 번 묻는다 |
| 되돌리기 / 다시 하기 | Ctrl+Z / Ctrl+Shift+Z, Ctrl+Y |
| 확대·축소 | 휠 또는 Ctrl+휠 |
| 화면 이동 | Space+끌기 또는 가운데 버튼 끌기 |
| 창에 맞춤 / 실제 크기 | Ctrl+0 / Ctrl+1 |
| 이전·다음 파일 | ← / → (글자 입력 중이 아닐 때) |

- 도구마다 **마지막 설정을 기억한다**(비율, 배경, 여백, 가리기 방식, 펜 색·굵기). 저장 위치는 `AppSettings.ImageTools`다.
- 저장을 누르면 창은 바로 닫히고, 처리는 알림 카드에서 보인다.

**여러 파일**
- 위쪽에 "3개 중 1"과 ‹ › 버튼을 둔다.
- 자르기, 배경 추가, 가리기: 설정 하나를 모든 파일에 쓴다. ‹ ›는 미리보는 파일만 바꾼다. 그래서 다른 파일에서도 상자가 제자리인지 확인할 수 있다.
- 주석: 파일마다 따로 그린다(그림 내용이 파일마다 다르니까). 아무것도 그리지 않은 파일은 저장하지 않는다. 아래쪽에 "표시한 2개만 저장돼요"라고 알려 준다.

**미리보기 = 결과 (가장 중요)**
- 미리보기와 저장은 같은 그리기 코드를 쓴다. `Filee.Engines`에 SkiaSharp으로 `ImageEditRenderer`를 만든다.
  - 미리보기: Avalonia 사용자 그리기(`ICustomDrawOperation`)에서 SKCanvas를 빌려 이 코드로 그린다.
  - 저장: `ImageEncoder.ApplyOptions`에서 `options.Edit`가 있으면 아래 순서로 처리한 뒤 기존 처리(품질, 메타데이터, 형식)를 그대로 이어 간다.
    1. EXIF 방향 바로잡기
    2. MagickImage를 RGBA로 바꿔 SKBitmap에 담기
    3. 렌더러로 그리기
    4. 다시 MagickImage로 되돌리기
- 편집 순서: 방향 바로잡기 → 자르기 → 가리기 → 주석 → 배경.
- 모든 위치와 크기는 **방향을 바로잡은 그림 기준 비율 값(0~1)**으로 저장한다. 선 굵기, 글자 크기, 여백, 모서리도 그림의 짧은 변에 대한 비율이다. 그래서 미리보기 배율이나 파일 크기가 달라도 결과 모양이 같다.
- 미리보기는 화면 크기로 줄인 그림으로 그린다. 원본 해상도는 저장할 때만 쓴다.
- 그림은 변환과 같은 Magick 읽기로 연다. HEIC, AVIF, WEBP도 그대로 열린다.

### 3.1 자르기 (묶음 1)
- 그림 위를 끌면 상자가 생긴다. 상자 안을 끌면 옮겨지고, 8개 손잡이로 크기를 바꾼다. 상자 밖은 어둡게 보인다. 끄는 동안 삼등분 격자가 보인다.
- 손잡이를 끌 때 Shift를 누르면 지금 비율을 지킨다. 상자 안을 더블클릭하면 저장된다.
- 패널 구성:
  - 비율 칩: 자유, 원본, 1:1, 16:9, 9:16, 4:3, 3:4. 입력 칸 밖에서는 숫자키 1~7로도 고른다.
  - W×H 픽셀 칸: 보고 있는 파일 기준이며 직접 입력할 수 있다.
- 처음 열면 마지막에 쓴 비율로, 그 비율의 가장 큰 가운데 상자가 잡혀 있다.
- 여러 파일, 크기가 다를 때:
  - 자유 비율: 비율 위치를 그대로 쓴다.
  - 고정 비율: 상자의 가운데 위치와 너비 비율을 지키고, 높이는 비율에 맞춰 다시 계산한다. 그림 밖으로 나가면 안쪽으로 밀어 넣는다.

### 3.2 배경 추가 (묶음 2)
- 패널 구성:
  - **배경:** 그라데이션 8개, 단색 6개(흰색, 검정, 회색, 피치, 하늘, 민트), 사용자 색(색 고르기), 사용자 그림(파일 선택, 꽉 채우기).
  - **여백:** 0~40%, 기본 8%
  - **모서리:** 0~25%, 기본 3%
  - **그림자:** 0~100, 기본 40
  - **비율:** 자동(그림 + 여백), 1:1, 16:9, 9:16, 4:5, 4:3. 고정 비율이면 여백을 최소값으로 두고 캔버스를 비율에 맞게 늘린 뒤 그림을 가운데 둔다.
- 슬라이더 옆에는 보고 있는 파일 기준 픽셀 값을 보여 준다(예: 609px). 저장은 비율 값으로 한다.
- 배경이 채워진 결과라서 투명한 곳이 없다. 그래도 화질 때문에 PNG로 저장한다.

### 3.3 가리기 (묶음 2)
- 그림 위를 끌면 가리는 상자가 생긴다. 클릭해서 고르고, 끌어서 옮기고, 손잡이로 크기를 바꾸고, Delete로 지운다.
- 방식은 **검은 상자**와 **모자이크** 두 가지이고, 모든 상자에 같이 적용된다. 모자이크 칸 크기는 `max(8px, 짧은 변/40)`이라서 다시 읽어 낼 수 없다.
- **흐리게(blur)는 넣지 않는다.** 일부가 복원될 수 있어서다.
- 결과는 **항상 메타데이터를 지운다.** EXIF 안의 작은 미리보기 그림에 가리기 전 모습이 남아 있을 수 있기 때문이다.

### 3.4 주석 (묶음 2)
- **도구와 단축키**

  | 도구 | 키 |
  |---|---|
  | 선택 | V |
  | 펜 | P |
  | 형광펜 | H |
  | 화살표 | A |
  | 선 | L |
  | 사각형 | R |
  | 원 | E |
  | 글자 | T |
  | 번호 스티커 | N |

  번호 스티커는 클릭할 때마다 1, 2, 3… 동그라미를 붙인다. 따라 하기용 스크린샷에 쓴다.
- **색과 굵기:** 색 8개 + 사용자 색. 굵기는 가늘게/보통/굵게이고 `[`와 `]`로 바꾼다. 글자 크기도 굵기를 따른다.
- 그린 것은 모두 **개체로 남는다.** 선택 도구로 옮기고 Delete로 지우며, 글자는 더블클릭해서 고친다. 되돌리기와 다시 하기는 개체 단위다.
- Shift를 누르면 선과 화살표는 0°, 45°, 90°로 꺾이고, 사각형과 원은 정사각형과 정원이 된다.
- 글자는 한글이 깨지지 않는 글꼴을 쓴다. 윈도우 기본은 맑은 고딕이고, 없으면 앱에 들어 있는 글꼴을 쓴다.

## 4. 피치 글래스 테마와 가운데 파일 크기

**고르는 곳.** 설정 › 모양 › 스타일에서 "Filee 기본"과 "피치 글래스" 중 고른다. Filee Plus를 처음 설치하면 피치 글래스가 기본이다. 밝게와 어둡게 둘 다 있다. (Tangerine은 다른 회사 앱 이름이라 테마 이름으로 쓰지 않는다.)

**유리 효과**
1. **화면 찍기:** 도넛 창을 띄우기 직전에 도넛이 덮을 화면 영역을 찍는다. 하위 링 자리까지 포함한다.
   - 드래그로 열 때는 `ShowForDrag`, 선택한 파일로 열 때는 `ShowForFiles`에서 찍는다.
   - 창은 아직 보이기 전이라 찍히지 않는다. 그래서 녹화나 스크린샷에는 도넛이 정상으로 나온다. (창을 화면 녹화에서 빼는 방식은 쓰지 않는다. 사용 영상을 찍을 때 도넛이 안 보이게 되기 때문이다.)
   - `IPlatformServices`에 기본 구현이 `null`을 돌려주는 `CaptureScreen(x, y, width, height)`를 더한다. Windows 구현은 데스크톱 DC에서 GDI BitBlt로 실제 픽셀을 찍는다. `CAPTUREBLT`를 쓰지 않으므로 탐색기 끌기 미리보기 같은 겹친 창은 찍히지 않는다.
2. **흐리게 하기:** 파일이 도넛에 들어왔을 때 한 번만 흐리게 한다. SkiaSharp 블러, 100% 배율 기준 sigma 약 20이고 DPI에 맞춘다. 결과는 열려 있는 동안 저장해 둔다.
3. **그리기:** `DonutMenu`가 도넛 모양으로 오려 그린다. 링, 가운데, 펼쳐진 하위 링이 모두 매 프레임 지금 모양을 따른다. 그 위에 피치 색 반투명 층을 덮고, 안쪽에 1px 밝은 테두리를 두고, 기존 그림자를 그린다.
4. **찍은 그림은 고정이다.** 열려 있는 동안 뒤 화면이 바뀌어도(동영상 등) 따라가지 않는다. 도넛은 잠깐 떠 있어서 괜찮다.
5. **대체 방식:** 다음 경우에는 블러 없이 반투명 피치 단색으로 그린다.
   - 찍기 실패, 검은 화면(DRM, 보안 데스크톱)
   - 창이 이미 떠 있을 때
   - macOS, Linux
6. **속도 목표:** 600×600px 기준으로 찍기와 블러를 합쳐 15ms 이하. 넘으면 절반 해상도로 줄여서 블러한다. 걸린 시간은 로그에 남긴다.

**색 (처음 값. 실제 화면에서 눈으로 맞춘다)**

| | 밝게 | 어둡게 |
|---|---|---|
| 칸 바탕 | `#FFE3CC` 70% | `#3A2418` 70% |
| 칸 강조 | `#FFC59A` | `#6B3A1F` |
| 가운데 | `#FFF6EE` 80% | `#2A1A10` 80% |
| 글자 | `#3B2416` | `#FFE9D9` |
| 강조색 | `#FF7A1A` | `#FF8A3D` |
| 도구 칸 | `#F2552C` | `#FF6A3D` |

값은 `Soft.axaml`의 테마 사전에 새 스타일 사전으로 넣는다. 알림 카드와 편집 창도 같은 강조색을 쓴다.

**가운데 파일 크기.** 두 테마 모두에 적용한다.
- 지금 가운데 제목 "1개 · JPG" 뒤에 크기를 붙인다.
  - 형식이 하나일 때: "1개 · JPG · 1.2 MB"
  - 섞였을 때: "3개 · 4.2 MB"
- 크기는 파일 크기를 더한 값이다. 탐색기처럼 1024 단위, KB/MB/GB, 소수 한 자리로 쓴다.
- 새 i18n 키를 쓰고, 기존 아래 줄 안내("JPG로 놓기" 등)는 그대로 둔다.

## 5. Shift 기본 동작

- Windows의 `TriggerGesture.Defaults()`를 세 개로 바꾼다. 다른 OS는 그대로다.
  1. **Shift + 드래그**(새로 추가)
  2. Ctrl + 드래그
  3. Ctrl+Alt+Space
- Tangerine처럼 **먼저 끌고 나중에 Shift를 눌러도** 열려야 한다. `GestureDetector.DetectLateModifier`가 Shift에서도 되는지 테스트로 확인한다.
- **원본 보호.** 탐색기에서 Shift + 드래그는 '이동'이라는 뜻이다. 도넛 창은 지금도 항상 COPY로 답한다(`RadialWindow.OnDragOver`의 주석 참고). 이 동작은 바꾸지 않는다. 실제 PC에서 Shift로 놓은 뒤 원본이 남는지 확인 목록에 넣는다.
- 파일 없이 끄는 동작은 지금처럼 아무것도 띄우지 않는다. 글자 선택, 범위 선택이 그런 동작이다. 기본 범위도 파일 관리자와 바탕화면이다. 그래서 Shift + 드래그로 글자를 선택해도 방해받지 않는다.
- **설정 이전은 하지 않는다.**
  - Filee Plus는 자기 설정 폴더를 쓰므로(6절) 처음 실행하면 새 기본값으로 시작한다.
  - 새 설정 항목(`ImageTools`, 스타일)은 기본값이 있어서 스키마 번호를 올리지 않는다.
  - 원본 Filee 설정 가져오기는 요청이 있을 때 만든다.

## 6. 포크 정체성과 배포

- **표시 이름은 "Filee Plus"다.** 프로젝트와 네임스페이스 이름(`Filee.*`)은 그대로 둔다. 업스트림과 합치기 쉽게 하려는 것이다.
- **원본 Filee와 같이 깔려도 부딪히지 않도록** 아래 항목을 바꾼다. 바꾸는 값은 한 곳(MSBuild 속성 또는 상수)에 모은다.
  - 제품 이름, 트레이 이름
  - Inno Setup `AppName`, `AppId`(새 GUID), 설치 폴더
  - 설정 폴더 `%APPDATA%\FileePlus`, 엔진 폴더 `%LocalAppData%\FileePlus\engines`, 임시 폴더
  - 한 번만 실행되게 하는 이름(뮤텍스)
  - 시작 프로그램 이름
  - 탐색기 오른쪽 메뉴의 이름, 레지스트리 키, CLSID, Windows 11 메뉴 패키지 이름
  - '보내기' 바로 가기 이름
- **원작자 쪽으로 가는 연결:** 피드백, 형식 요청 같은 곳은 포크 저장소로 바꾸거나 끈다. 원작자가 만들지 않은 기능의 오류 보고를 받지 않게 하려는 것이다. 후원 창은 원작자 후원으로 그대로 둔다.
- **업데이트:** Filee에 이미 있는 자동 업데이트(`UpdateService`)를 그대로 쓴다.
  - 동작: 앱이 켜진 직후와 그 뒤 6시간마다 GitHub 저장소의 최신 릴리스를 확인한다. 새 버전이 있으면 바뀐 내용과 함께 알린다. '업데이트'를 누르면 설치 파일을 받아 SHA-256을 확인한 뒤 진행 창만 띄워 설치하고, 설정을 지킨 채 다시 켠다. 설치할 때 관리자 확인이 한 번 뜬다. 압축(포터블)판은 다운로드 페이지를 연다.
  - `FileeRepositoryUrl`을 사용자의 GitHub 포크 주소로 바꾼다. 저장소는 **공개**여야 한다. 비공개면 로그인 없이 릴리스를 볼 수 없어서 확인이 404로 실패한다.
  - `UpdateService.WebsiteUrl`(`https://filee.sh/`, 원작자 사이트)을 포크의 `/releases/latest`로 바꾼다. 설치판에서 업데이트가 실패하면 이 주소가 열린다.
  - 포크를 만들기 전까지는 주소를 비워 업데이트 확인을 끈다. 빈 주소일 때 꺼지게 만든다.
  - 새 버전 내기: 버전을 올리고 `v1.0.1` 같은 태그를 푸시한다. 기존 `.github/workflows/release.yml`이 설치 파일, 포터블 zip, 체크섬을 만들어 GitHub 릴리스에 올린다. 그러면 모든 사용자의 앱이 6시간 안에 찾아낸다.
- **버전:** Filee Plus 1.0.0부터 따로 센다. 정보 화면에 "Filee 1.12.0 기반"이라고 보여 준다.
- **저작권:** LICENSE와 THIRD-PARTY-NOTICES를 그대로 둔다. README와 정보 화면에 "KnifeLemon의 Filee(MIT)를 바탕으로 함"이라고 적는다. 새 외부 라이브러리는 추가하지 않는다. SkiaSharp과 Magick.NET은 이미 쓰고 있다.
- **설치 파일:** 기존 `build/build-installer.ps1`로 만든다. 이름은 `FileePlus-<버전>-win-Setup.exe`, 체크섬은 `FileePlus-<버전>-SHA256SUMS.txt`다. 업데이트 기능은 끝이 `-win-Setup.exe`와 `-SHA256SUMS.txt`인 파일을 찾으므로(`UpdateService.FindFiles`) 이 끝부분은 바꾸지 않는다.
- **코드 서명:** 하지 않는다. 다른 사람 PC에서 SmartScreen 경고가 뜨므로 README에 "추가 정보 → 실행"을 안내한다.
- **이 PC의 빌드 준비:** .NET 10 SDK가 없다(런타임 8.0만 있음). winget으로 설치한다. 설치 파일을 만드는 데 필요한 Zig와 Inno Setup은 빌드 스크립트 안내를 따른다.

## 7. 테스트

**자동 테스트 (기존 xunit 프로젝트에 추가)**
- Core
  - `tools` 그룹에 6개 칸이 들어 있다.
  - Tool 프리셋은 프리셋 목록, 감시 폴더, CLI에 나오지 않는다.
  - 이미지 기본 프로필에 도구 칸이 있다.
  - Windows 기본 동작에 Shift + 드래그가 있다.
  - 비율 좌표 계산: 고정 비율 다시 계산, 그림 밖으로 나간 상자 밀어 넣기.
- Engines (실제 그림으로, `EngineFixture`)
  - 자르기 결과 크기가 맞다. EXIF로 돌아간 JPG에서도 눈에 보이는 영역이 잘린다.
  - 압축·메타데이터 지우기: EXIF 방향 정보가 지워져도 사진 방향이 그대로다.
  - 가리기: 상자 안이 모두 검정이거나 모자이크 칸이 고르다. 결과에 EXIF와 그 안의 미리보기가 없다.
  - 배경: '자동' 결과 크기는 그림 + 여백×2이다. 16:9는 비율이 정확하다. 모서리 바깥은 배경색이다.
  - 주석: 빨간 선이 지나간 픽셀이 바뀐다. 한글 글자가 그려진다(빈 그림이 아니다).
  - 같은 결과: 25% 배율로 그린 것과 100% 배율로 그려 줄인 것이 허용 오차 안에서 같다.
- App
  - GestureDetector: 늦게 누른 Shift에서도 열린다.
  - 헤드리스 그리기: 가짜로 찍은 그림으로 피치 글래스가 그려진다. 찍기가 `null`이면 단색으로 그려진다.
  - i18n: 새 키가 6개 언어 파일에 모두 있다(기존 `LocalizationResourceTests`). 영어·한국어 외 4개 언어는 번역해서 넣는다.

**실제 PC에서 확인할 목록**
- 탐색기와 바탕화면에서 Shift + 드래그로 도넛이 뜨고, 놓은 뒤 원본이 그대로 있다.
- 배율이 다른 모니터 두 대에서 유리 효과가 제자리에 비친다. 어둡게 모드도 확인한다.
- 편집 창이 다른 창 뒤에 숨지 않고 앞으로 나온다.
- HEIC, WEBP를 열 수 있다. 50개 파일을 한 번에 잘라도 문제없다.
- 가능하면 Windows 10에서도 확인한다.

**CI:** 기존 워크플로(`dotnet format --verify-no-changes`, 전체 테스트)를 그대로 쓴다.

- 투명 배경 출력
- 원본 Filee 설정 가져오기
- 코드 서명

- 업스트림 기능 삭제
